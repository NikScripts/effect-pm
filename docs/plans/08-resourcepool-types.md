# ResourcePool — Types & Interfaces

Unlike the other docs in this set, the types here are settled. Names, shapes, and signatures are decided unless explicitly noted otherwise.

---

## Pool Interface

```ts
interface ResourcePool<T, R, E = never> {
  // priority add methods
  // bump — high priority
  // add  — normal priority
  // defer — low priority
  readonly bump: (item: T | readonly T[]) => Effect<void>
  readonly add: (item: T | readonly T[]) => Effect<void>
  readonly defer: (item: T | readonly T[]) => Effect<void>

  readonly size: () => Effect<number>
  readonly sizeByPriority: () => Effect<{ high: number; normal: number; low: number }>
  readonly isEmpty: () => Effect<boolean>
  readonly getCompleted: () => Effect<number>

  readonly pause: () => Effect<void>
  readonly resume: () => Effect<void>
  readonly shutdown: () => Effect<void>
  readonly restart: () => Effect<void>

  // internal — keeps worker fibers alive, do not access directly
  // void is the success type of the fiber — workers run indefinitely and return nothing
  readonly _workers: readonly Fiber.RuntimeFiber<void>[]
}
```

## Record Types

Three phases. Each extends the previous. `QueueRecord` is the union used for storage reads where the phase is unknown.

```ts
// ─── Phase 1 — created on enqueue ────────────────────────────────────────────

interface EnqueuedRecord<T> {
  id: string              // generated by PM on enqueue — unique per enqueue event
  key?: string            // derived from item via getKey — stable across runs, enables history
  resourceId: string      // name of the ResourcePool this item belongs to
  item: T                 // raw item or Schema.Encoded<T> if schema provided
  priority: "high" | "normal" | "low"
  enqueuedAt: Date
  hasForkWith: boolean    // derived from whether forkWith is provided in config
  history?: QueueRecord<T, R, E>[]  // previous runs for this key+resourceId, most recent first
                                     // only present if getKey is provided
}

// ─── Phase 2 — after effect completes ────────────────────────────────────────

interface EffectCompleteRecord<T, R, E> extends EnqueuedRecord<T> {
  effect: {
    exit: Exit.Exit<R, E>   // not stored — available in onEffectComplete hook only
    status: "success" | "failure" | "defect" | "interrupted"
    value?: R               // populated on success
    error?: E               // populated on typed failure
    defect?: unknown        // populated on defect
    startedAt: Date
    completedAt: Date
    duration: Duration
  }
}

// ─── Phase 3 — after forkWith completes ──────────────────────────────────────

interface ForkCompleteRecord<T, R, E> extends EffectCompleteRecord<T, R, E> {
  fork: {
    status: "success" | "defect" | "interrupted"
    defect?: Cause.Cause<never>   // only ever a defect — E is never in forkWith
    startedAt: Date
    completedAt: Date
    duration: Duration
  }
}

// ─── Union — used for storage reads ──────────────────────────────────────────

type QueueRecord<T, R, E> =
  | EnqueuedRecord<T>
  | EffectCompleteRecord<T, R, E>
  | ForkCompleteRecord<T, R, E>
```

## Storage Config

```ts
interface StorageConfig<T, R, E> {
  // only required if T is not directly storable
  schema?: Schema.Schema<T, unknown>

  // called when item is enqueued — forked, non-blocking
  // replaces old top-level `cache` config field
  onEnqueued?: (
    record: EnqueuedRecord<T>,
    store: (record: EnqueuedRecord<T>) => Effect<void>,
    pool: ResourcePool<T, R, E>
  ) => Effect<void>

  // called after effect completes
  onEffectComplete?: (
    record: EffectCompleteRecord<T, R, E>,
    store: (record: EffectCompleteRecord<T, R, E>) => Effect<void>,
    pool: ResourcePool<T, R, E>
  ) => Effect<void>

  // called after forkWith completes — only fires if forkWith is provided
  onForkComplete?: (
    record: ForkCompleteRecord<T, R, E>,
    store: (record: ForkCompleteRecord<T, R, E>) => Effect<void>,
    pool: ResourcePool<T, R, E>
  ) => Effect<void>

  // called when pool is empty — replaces old top-level `refill` config field
  onEmpty?: (
    pool: ResourcePool<T, R, E>,
    pending: (
      filter?: (record: QueueRecord<T, R, E>) => boolean
    ) => Effect<QueueRecord<T, R, E>[]>,
    fill: (records: QueueRecord<T, R, E>[]) => Effect<void>
  ) => Effect<void>

  // called when item hits maxRetries — storage concern only
  // use for dead letter storage, marking item as exhausted, etc.
  onMaxRetries?: (
    record: EnqueuedRecord<T>,
    store: (record: EnqueuedRecord<T>) => Effect<void>,
    pool: ResourcePool<T, R, E>
  ) => Effect<void>
}
```

## Pool Config

```ts
interface ResourcePoolConfigBase<T, R, E = never> {
  readonly name: string
  readonly effect: (item: T) => Effect<R, E>
  readonly capacity?: number
  readonly concurrency?: number
  readonly throttle?: {
    readonly limit: number
    readonly duration: Duration
  }

  // only available when getKey is provided
  readonly getKey?: (item: T) => string

  // keyed behavior — only meaningful when getKey is provided
  readonly skipDuplicates?: boolean   // skip enqueue if item already succeeded — default false
  readonly maxRetries?: number        // max consecutive failures since last success

  // behavior hook — top level, not a storage concern
  // called when item hits maxRetries — use for alerting, re-routing, dead letter, etc.
  readonly onMaxRetries?: (
    record: EnqueuedRecord<T>,
    pool: ResourcePool<T, R, E>
  ) => Effect<void>

  readonly storage?: StorageConfig<T, R, E>
}

type ResourcePoolConfig<T, R, E = never, RFork = never> =
  ResourcePoolConfigBase<T, R, E> &
    ([E] extends [never]
      ? {
          // optional when E is never
          readonly forkWith?: (
            forked: Effect<R, E>,
            item: T,
            pool: ResourcePool<T, R, E>
          ) => Effect<void, never, RFork>
        }
      : {
          // required when E is not never
          readonly forkWith: (
            forked: Effect<R, E>,
            item: T,
            pool: ResourcePool<T, R, E>
          ) => Effect<void, never, RFork>
        })
```

## Enqueue Flow

When `bump`, `add`, or `defer` is called:

1. PM generates a unique `id` for this enqueue event
2. If `getKey` is provided — derive `key` from item, look up history from storage using `key + resourceId`
3. If `skipDuplicates: true` — check history for a successful run, skip enqueue if found
4. If `maxRetries` is set — count consecutive failures from history, call `onMaxRetries` and skip enqueue if at limit
5. Build `EnqueuedRecord` with `id`, `key`, `resourceId`, `item`, `priority`, `enqueuedAt`, `hasForkWith`, `history`
6. Fork `storage.onEnqueued` — non-blocking, does not delay enqueue
7. Add item to the appropriate priority queue

## Notes

**`store` function in storage hooks** — the second arg in `onEnqueued`, `onEffectComplete`, `onForkComplete`, and `onMaxRetries`. This is the package-level storage service function for that hook, pre-wired with the pool context. Call it to persist using the default service, ignore it to use your own storage entirely, or do work around it. The pool itself is not passed to `store` — the service already has it.

**`exit` field** — `EffectCompleteRecord.effect.exit` is an Effect `Exit` object. It is available in the `onEffectComplete` hook for full `Cause` inspection (fiber traces, parallel/sequential causes, annotations). It is not stored — the storage service receives a record without `exit`. The convenience fields (`value`, `error`, `defect`, `status`) are what get persisted.

**Service layer per pool** — to use a custom storage service for a specific pool, provide the layer directly to that pool's effect using standard Effect composition. No special package support needed:

```ts
const MyPool = ResourcePool.make({ ... })
  .pipe(Effect.provide(MyCustomStorageLayer))
```

**`history` size** — loading full history on every enqueue could be expensive. A `historyLimit` option on the config caps how many records are loaded. Default TBD during implementation.

**`onMaxRetries` — two hooks** — there are two separate `onMaxRetries` hooks: one at the top level of the config (behavior concern — alerting, re-routing) and one under `storage` (storage concern — dead letter table, marking exhausted). Both are optional and independent.

**Consecutive failures** — `maxRetries` counts consecutive failures since the last success. If there are any successes in history, the count resets. Only failures since the most recent success count toward the limit.
