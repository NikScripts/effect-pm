# Dashboard Transport Rewrite + ProcessStore Remote Layer — API Design

## Goals

1. Add a **query-only `.Query` sub-tag** to every facet (strips emit surface for remote consumers)
2. Write **Schema definitions** for all fact/change types so they can travel over Effect RPC
3. Build **`StoreTransportRpc`** — a new RPC module exposing all facet read methods
4. Add **`layerRemote(client)`** to every facet (routes queries over RPC, provides `.Query` tag)
5. Rewrite the dashboard to consume facet query views over RPC instead of HTTP polling

---

## Decision log

| Question | Decision |
|---|---|
| QueryView placement | `Facet.Query` sub-tag auto-generated by builder |
| Output Schema | Full `Schema.Schema` for every fact/change type (not `Schema.Unknown`) |
| RPC group structure | One `StoreRpc` group with one operation per facet method |
| Dashboard API | New `DashboardPort` interface; `ControlPlanePort` and `controlHttp.ts` deleted |

## Part 1 — `.Query` sub-tag on every facet

The `ProcessStore.Service` builder auto-generates a read-only sub-tag alongside every facet:

```ts
// What you get today
QueueResourceStore              // Context.Tag — yields EmitApi & QueryApi
QueueResourceStore.layer        // Layer<QueueResourceStore, never, never>
QueueResourceStore.layerRuntimeStorage
QueueResourceStore.Entry.Enqueued(...)    // static emit
QueueResourceStore.for("@app/Email")      // Effect<IdentifierApi, never, QueueResourceStore>

// New additions (auto-generated by builder for every facet)
QueueResourceStore.Query              // Context.Tag — yields QueryApi ONLY, no emit surface
QueueResourceStore.layerQuery         // Layer<QueueResourceStore.Query, never, QueueResourceStore>
QueueResourceStore.layerRemote(client) // Layer<QueueResourceStore.Query, never, never>
```

### Usage on the dashboard

```ts
// Dashboard code — cannot accidentally call emit
const store = yield* QueueResourceStore.Query
//    ^-- type is { entries, entriesByKey, lifecycle, dedupeKeys, rateLimits }
//        NO Entry.Enqueued, NO Lifecycle.Started — emit surface is gone

const facts    = yield* store.entries({ queueId: "@app/Email" })
const byKey    = yield* store.entriesByKey("user-42")
const lifecycle = yield* store.lifecycle({ queueId: "@app/Email" })
```

### Tag ID convention

Sub-tag ID = facet ID + `/Query`. So `QueueResourceStore.Query` has context ID:
```
"@nikscripts/effect-pm/store/queueResource/QueueResourceStore/Query"
```

### New type alias in `ProcessStore` namespace

```ts
export declare namespace ProcessStore {
  export namespace Service {
    // existing...
    export type QueryTag<T> = ProcessStoreFacetQueryTag<T>  // type of the .Query sub-tag
  }
}
```

## Part 3 — `StoreTransportRpc` module

New file: `src/StoreTransportRpc.ts`. Mirrors the shape of `ControlTransportRpc.ts` and `LogTransportRpc.ts` exactly.

### Error type

```ts
export const StoreRpcErrorSchema = Schema.TaggedStruct("StoreRpcError", {
  reason: Schema.String,
})
export type StoreRpcError = typeof StoreRpcErrorSchema.Type
```

### RPC group

```ts
export const StoreRpc = RpcGroup.make(
  // ── QueueResource ──────────────────────────────────────────────────────────
  Rpc.make("Store.QueueResource.Entries", {
    payload: QueueEntryQuerySchema,
    success: Schema.Array(QueueEntryFactSchema),
    error:   StoreRpcErrorSchema,
  }),
  Rpc.make("Store.QueueResource.EntriesByKey", {
    payload: EntryByKeyQuerySchema,
    success: Schema.Array(QueueEntryFactSchema),
    error:   StoreRpcErrorSchema,
  }),
  Rpc.make("Store.QueueResource.Lifecycle", {
    payload: QueueLifecycleQuerySchema,
    success: Schema.Array(QueueLifecycleChangeSchema),
    error:   StoreRpcErrorSchema,
  }),
  Rpc.make("Store.QueueResource.DedupeKeys", {
    payload: QueueDedupeKeyQuerySchema,
    success: Schema.Array(QueueDedupeKeyChangeSchema),
    error:   StoreRpcErrorSchema,
  }),
  Rpc.make("Store.QueueResource.RateLimits", {
    payload: QueueRateLimitQuerySchema,
    success: Schema.Array(QueueRateLimitExceededFactSchema),
    error:   StoreRpcErrorSchema,
  }),
  // ── ProcessLifecycle ───────────────────────────────────────────────────────
  Rpc.make("Store.ProcessLifecycle.Events", {
    payload: ProcessLifecycleQuerySchema,
    success: Schema.Array(ProcessLifecycleEventSchema),
    error:   StoreRpcErrorSchema,
  }),
  // ── ProcessExecution ───────────────────────────────────────────────────────
  Rpc.make("Store.ProcessExecution.Events", {
    payload: ProcessExecutionQuerySchema,
    success: Schema.Array(ProcessExecutionEventSchema),
    error:   StoreRpcErrorSchema,
  }),
  // ── ProcessGroup ───────────────────────────────────────────────────────────
  Rpc.make("Store.ProcessGroup.Events", {
    payload: ProcessGroupQuerySchema,
    success: Schema.Array(ProcessGroupEventSchema),
    error:   StoreRpcErrorSchema,
  }),
  // ── RunResource ────────────────────────────────────────────────────────────
  Rpc.make("Store.RunResource.Runs", {
    payload: RunResourceQuerySchema,
    success: Schema.Array(RunResourceEventSchema),
    error:   StoreRpcErrorSchema,
  }),
  // ── Log (history; live streaming stays in LogTransportRpc) ────────────────
  Rpc.make("Store.Log.Entries", {
    payload: LogQuerySchema,
    success: Schema.Array(LogEntrySchema),
    error:   StoreRpcErrorSchema,
  }),
)

export type StoreRpcClient<E = never> = RpcClient.FromGroup<typeof StoreRpc, E>
```

### Server handler layer

```ts
const toStoreRpcError = (e: unknown): StoreRpcError => ({
  _tag: "StoreRpcError",
  reason: e instanceof Error ? e.message : String(e),
})

export const StoreTransportRpcLive = StoreRpc.toLayer({
  "Store.QueueResource.Entries":      (q) =>
    Effect.flatMap(QueueResourceStore, (s) => s.entries(q)).pipe(Effect.mapError(toStoreRpcError)),
  "Store.QueueResource.EntriesByKey": ({ key, ...q }) =>
    Effect.flatMap(QueueResourceStore, (s) => s.entriesByKey(key, q)).pipe(Effect.mapError(toStoreRpcError)),
  "Store.QueueResource.Lifecycle":    (q) =>
    Effect.flatMap(QueueResourceStore, (s) => s.lifecycle(q)).pipe(Effect.mapError(toStoreRpcError)),
  "Store.QueueResource.DedupeKeys":   (q) =>
    Effect.flatMap(QueueResourceStore, (s) => s.dedupeKeys(q)).pipe(Effect.mapError(toStoreRpcError)),
  "Store.QueueResource.RateLimits":   (q) =>
    Effect.flatMap(QueueResourceStore, (s) => s.rateLimits(q)).pipe(Effect.mapError(toStoreRpcError)),
  "Store.ProcessLifecycle.Events":    (q) =>
    Effect.flatMap(ProcessLifecycleStore, (s) => s.events(q)).pipe(Effect.mapError(toStoreRpcError)),
  "Store.ProcessExecution.Events":    (q) =>
    Effect.flatMap(ProcessExecutionStore, (s) => s.events(q)).pipe(Effect.mapError(toStoreRpcError)),
  "Store.ProcessGroup.Events":        (q) =>
    Effect.flatMap(ProcessGroupStore, (s) => s.events(q)).pipe(Effect.mapError(toStoreRpcError)),
  "Store.RunResource.Runs":           (q) =>
    Effect.flatMap(RunResourceStore, (s) => s.runs(q)).pipe(Effect.mapError(toStoreRpcError)),
  "Store.Log.Entries":                (q) =>
    Effect.flatMap(LogStore, (s) => s.entries(q)).pipe(Effect.mapError(toStoreRpcError)),
})
```

### Public namespace (mirrors `ControlTransportRpc` / `LogTransportRpc`)

```ts
export interface StoreTransportRpcApi {
  readonly rpc:         typeof StoreRpc
  readonly live:        typeof StoreTransportRpcLive
  readonly serverLayer: (config?: StoreTransportRpcServerConfig) =>
    Layer.Layer<never, never, RpcServer.Protocol | AllFacetServices>
  readonly clientLayer: <E>(client: StoreRpcClient<E>) =>
    Layer.Layer<StoreTransportClient>
}

export const StoreTransportRpc: StoreTransportRpcApi = {
  rpc:  StoreRpc,
  live: StoreTransportRpcLive,
  serverLayer: (config = {}) =>
    Layer.effectDiscard(
      Effect.flatMap(RpcServer.Protocol, (protocol) =>
        RpcServer.make(StoreRpc, config).pipe(
          Effect.provide(StoreTransportRpcLive),
          Effect.provideService(RpcServer.Protocol, protocol),
        )
      ),
    ),
  clientLayer: (client) =>
    Layer.succeed(StoreTransportClient, client),
}
```

## Part 4 — `layerRemote` and `layerQuery` on each facet

These are added by the builder in `src/internal/store/service.ts` — no per-facet hand-wiring needed. Concretely, for `QueueResourceStore`:

```ts
// Server-side: expose the .Query sub-tag from the local full facet
// (strips emit half from the instance shape)
QueueResourceStore.layerQuery = Layer.effect(
  QueueResourceStore.Query,
  Effect.map(QueueResourceStore, (s) => ({
    entries:      (q?)       => s.entries(q),
    entriesByKey: (key, q?)  => s.entriesByKey(key, q),
    lifecycle:    (q?)       => s.lifecycle(q),
    dedupeKeys:   (q?)       => s.dedupeKeys(q),
    rateLimits:   (q?)       => s.rateLimits(q),
  }))
)

// Dashboard / client-side: route queries over RPC, provide .Query sub-tag
QueueResourceStore.layerRemote = (client: StoreRpcClient) =>
  Layer.succeed(QueueResourceStore.Query, {
    entries:      (q?)      => client["Store.QueueResource.Entries"](q ?? {}),
    entriesByKey: (key, q?) => client["Store.QueueResource.EntriesByKey"]({ key, ...q }),
    lifecycle:    (q?)      => client["Store.QueueResource.Lifecycle"](q ?? {}),
    dedupeKeys:   (q?)      => client["Store.QueueResource.DedupeKeys"](q ?? {}),
    rateLimits:   (q?)      => client["Store.QueueResource.RateLimits"](q ?? {}),
  })
```

### Idiomatic: one ManagedRuntime with all remote layers

```ts
const dashboardRuntime = ManagedRuntime.make(
  Layer.mergeAll(
    ProcessStorage.layerRemote(rpcClient),        // provides all .Query tags
    ControlTransportRpc.clientLayer(rpcClient),   // provides ControlTransportClient
    LogTransportRpc.clientLayer(rpcClient),       // provides LogTransportClient
  )
)

// Build a concrete DashboardPort from the runtime
const port: DashboardPort = {
  queueEntries:     (q) => dashboardRuntime.runPromise(
    Effect.flatMap(QueueResourceStore.Query, (s) => s.entries(q))
  ),
  queueLifecycle:   (q) => dashboardRuntime.runPromise(
    Effect.flatMap(QueueResourceStore.Query, (s) => s.lifecycle(q))

  processLifecycle: (q) => dashboardRuntime.runPromise(
    Effect.flatMap(ProcessLifecycleStore.Query, (s) => s.events(q))
  ),
  dispatch: (req) => dashboardRuntime.runPromise(
    Effect.flatMap(ControlTransportClient, (c) => c.request(req))
  ),
  logStream: (req) => /* AsyncIterable from LogTransportClient */,
}
```

### Dashboard effect code

Once the runtime is set up, dashboard Effects look identical to server-side code — just with remote layers underneath:

```ts
const refreshStatus = Effect.gen(function* () {
  const queues    = yield* QueueResourceStore.Query
  const lifecycle = yield* ProcessLifecycleStore.Query

  const [recentEntries, queueLifecycle, processEvents] = yield* Effect.all([
    queues.entries({ opts: { limit: 100, order: "desc" } }),
    queues.lifecycle({ opts: { limit: 50,  order: "desc" } }),
    lifecycle.events({ opts: { limit: 50,  order: "desc" } }),
  ])

  return { recentEntries, queueLifecycle, processEvents }
})
```

## Open questions

1. **`DashboardPort.queueEntries` vs higher-level `processStatus()`** — the new port returns raw facet events. Do the status tables need a projection layer (e.g. "current lifecycle state per process") or is raw event arrays fine?

2. **`layerRemote` in the builder vs standalone** — currently proposed as auto-generated by the builder (requires the builder to know about `StoreRpcClient` type). Alternative: `layerRemote` lives only in `StoreTransportRpc.ts` as a standalone factory, not on the facet class. Tradeoff: standalone is decoupled (no transport import in `store/`) but less discoverable.

3. **`for(id)` on `.Query`** — should `QueueResourceStore.Query.for("@app/Email")` work? Currently `for()` is a static method on the full facet class that returns `Effect<IdentifierApi, never, QueueResourceStore>`. For the `.Query` sub-tag it would need to return `Effect<IdentifierApi, never, QueueResourceStore.Query>` instead.
